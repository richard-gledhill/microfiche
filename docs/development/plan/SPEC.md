# SPEC: scriptable output (`scriptable-output`)

Source: [scriptable-output-prd.md](../requirements/scriptable-output-prd.md), decided in
[ADR-010](../adr/ADR-010-scriptable-output.md). Style and bar: [conventions.md](../conventions.md),
[constraints.md](../constraints.md). Two PRs: **A, `--json`** (this one), then **B, the `file` command**.

## Scope of A

- `cli/json_output.py`: Pydantic output models (`SortOutput`, `ReclassifyOutput`, `RollbackOutput`, `AuditOutput`,
  `ConfigOutput`, `ReviewQueueOutput`, `ErrorOutput`), each with `version` (1) and `command`; builders from the core types.
  No document text.
- `--json` on `sort`, `reclassify`, `rollback`, `audit`, `config` (and `config --sync`), and `review --list`. With it,
  `commands.console` is the stderr console for the run and stdout gets one document; a `_fail` also emits an `ErrorOutput`.
- `review --list` prints the queue without a terminal (one line per unit, or JSON); `review --json` without `--list` is
  refused.
- `schemas/<command>.schema.json`, generated by `make output-schemas`, with a test that fails when stale.
- `pydantic` becomes a direct dependency of the `cli` package.

## Done when

- `sort --dry-run --json` parses, validates against its model and lists every inbox unit once; stdout holds only the
  document even with `-v`; failures are JSON on stdout with exit 1.
- Docs and the CLI reference describe `--json`.
