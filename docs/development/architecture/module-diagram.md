# Module diagram

Two Mermaid diagrams. The first, the import graph, is generated by `make module-diagram` from the actual
`packages/core/src/microfiche/core` and `packages/cli/src/microfiche/cli` source (the import statements, not the prose in
[architecture/overview.md](overview.md)) as of 2026-10-31; that date moves when the graph changes. The second, the
runtime data flow, is written by hand. If the first drifts from the code, trust the code and regenerate it
rather than editing it to match a stale diagram.

## 2. Sort pipeline data flow

What actually happens at runtime when `microfiche sort` runs, as opposed to what imports what.

```mermaid
flowchart TD
    LibraryTree[("Library folder tree\n(group/category subfolders)")]
    SortingInbox[("inbox (_sorting/ by default)\n(loose files + folders)")]
    ConfigFile[("microfiche-config.toml\n(over the packaged defaults)")]
    LibraryFileJson[("microfiche-library.json\n(hints and filename rules)")]

    LibraryTree -->|"Library.taxonomy()"| Taxonomy["Taxonomy\n{group: [category, ...]}"]
    ConfigFile -->|"load_config()"| Config["MicroficheConfig"]
    LibraryFileJson -->|"load_library_file()\n(checked against depth)"| LibraryFile["LibraryFile\n(folder tree: hints, rules)"]
    SortingInbox -->|"scan_sorting_inbox()"| Units["SortableUnit(s)\n(a file, or a folder if keep_folders;\nelse each file in a folder, with its origin_folder)"]
    Units -->|"read_documents() via parsers/"| Documents["Document(s)\n(text + metadata)"]
    Units -.->|"a file that can't be read:\nno document, left for review with the reason"| NeedsReview

    Documents --> ClassifyUnit["Classifier.classify_unit()"]
    Taxonomy --> ClassifyUnit
    LibraryFile -->|"hints_for / rules_for"| RulesEngine
    Config -.->|"match strengths,\nfuzzy threshold"| RulesEngine
    ClassifyUnit --> RulesEngine["RulesEngine\n(group_rules -> keyword_rules/metadata_rules\n-> confidence.combine_confidence, min not average)"]
    RulesEngine -->|"confident: both stages resolved and\nconfidence >= threshold (default 0.75)"| Result["ClassificationResult"]
    RulesEngine -->|"a stage below threshold and --use-ai\n(asked per stage, group then category)"| LLM["LLMClassifier\n(Ollama or OpenAI, built from [ai]\nby build_provider)"]
    LLM --> Result
    LLM -.->|"provider fails once: asked no more this run;\nthe rules' answers stand, one warning"| Result

    Result -->|"file unit, same content as a library file\nor one filed earlier in the run"| Duplicates[["SortReport.duplicates\n(left in the inbox, with where the copy is)"]]
    LibraryTree -.->|"DuplicateIndex: sizes first,\nhash only same-size files"| Duplicates
    Result -->|">= threshold, not a duplicate"| Claim{"DestinationClaims.claim()\nname taken?"}
    Claim -->|"free"| FileUnit["filer.file_batch()\n(one Job per run; a move is a plain rename)"]
    Claim -.->|"--dry-run: stop here, nothing is written"| Preview[["SortReport only\n(labelled a preview)"]]
    RunLock[(".microfiche/lock\n(sort, reclassify --apply, rollback,\nconfig --sync, review)")] -.->|"taken before the run starts,\nreleased when it ends"| FileUnit
    FileUnit -.->|"a move fails (file open in Word):\nstays in the inbox, nothing recorded"| NeedsReview
    Claim -->|"taken"| NeedsReview[["SortReport.needs_review\n(worked through by microfiche review)"]]
    Result -->|"< threshold"| NeedsReview

    FileUnit --> FiledDoc[("moved into\nresolved group/category folder")]
    FileUnit --> Ledger[(".microfiche/ledger.jsonl\n(what, where, why; keyed by path + hash)")]
    FileUnit --> AuditLog[(".microfiche/audit.log\n(one line per move)")]
    FileUnit --> JobFile[(".microfiche/rollback/job_ID.json")]
    FileUnit -->|"keep_folders off: inbox folder left empty"| RemoveFolder["rmdir, recorded as remove_folder\n(rollback recreates it)"]
    RemoveFolder --> JobFile
    JobFile -->|"rollback_job()"| Rollback["replays the Job's moves\nin reverse order"]
    Rollback --> Ledger
    Rollback --> AuditLog

    classDef gap fill:#fff3cd,stroke:#c9a227,stroke-width:2px
    class NeedsReview gap
```

Solid arrows are wired end to end today; dashed arrows and the highlighted box are the `review` queue, which
`microfiche review` works through (`core/review.py`) and files with the same `file_batch`.
`reclassify.py` reuses `Classifier`/`RulesEngine` the same way against already-filed documents
instead of the `_sorting/` inbox; with `--apply` it files its `move` proposals through the same
`filer.file_batch`, so a reclassification is a job like any other.
